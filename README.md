## Overview
Untitled Tower Defense is a small-scale real-time strategy game developed in **Unity**. My official role was Product Owner, but due to team constraints, I became the sole engineer for the project. My primary responsibility was to design and implement all core game logic, systems, and architecture to deliver a Minimum Viable Product (MVP) that met all course requirements.

### My Core Contributions:
-   **Full Game Logic:** Implemented all gameplay mechanics from scratch.
-   **Architectural Design:** Established the code architecture and designed the event-driven communication system.
-   **Wave Spawning System:** Built a robust system for managing and spawning enemy waves.
-   **Pathfinding:** Designed and implemented enemy pathfinding logic.
-   **UI & Game State Management:** Developed the user interface and handled game state transitions.

---

## Key Technical Features
-   **Event-Driven Architecture:** The game utilizes C# events to manage communication between disparate game objects, such as UI elements, audio cues, and the core game loop. This reactive system allows for a highly modular and extensible codebase.
-   **Scriptable Object Wave Spawner:** The wave spawning system is configured using Scriptable Objects. This approach eases the computational burden of loading and managing enemy waves at runtime, making it highly efficient.
-   **Modular Game Systems:** I designed a modular system that allowed for the creation of new tower types, enemies, and weapons with minimal effort, even though our limited scope meant we only implemented three of each.

## Problem-Solving & Leadership Under Pressure
This project presented significant challenges beyond the technical implementation. As Product Owner, I was tasked with guiding a team that struggled with communication and collaboration.

-   **Scope Management:** I continuously managed the project scope, working to meet minimum viable product requirements as team contributions diminished. This involved direct communication with the course instructor to re-evaluate project goals and set realistic, achievable deadlines.
-   **Technical Integration:** I became the central point of integration, responsible for incorporating code and assets from various team members, sometimes receiving contributions as plain text due to version control difficulties. I successfully integrated all viable work while maintaining a cohesive and functional codebase.

---

## Lessons Learned & Future Improvements
Despite the internal challenges, this project was a valuable experience that taught me critical lessons about collaborative software development and project management.

-   **Team Dynamics & Communication:** I learned firsthand the importance of clear communication channels and consistent participation.
-   **Setting Boundaries:** This project reinforced the need for setting and maintaining realistic personal work boundaries to ensure sustainable development.
-   **Future Improvements:** If I were to continue development, I would focus on integrating the advanced pathfinding system that was built but never fully implemented. I would also implement the modular enemy and tower systems the got put on the back-burner to enable further content development.
